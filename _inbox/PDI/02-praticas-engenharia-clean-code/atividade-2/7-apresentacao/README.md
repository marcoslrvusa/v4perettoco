# Pipeline de Testes Automatizados (Unit/Integration/E2E) com 80% de Cobertura

Engenharia de Software

<h2><span class="num">1.</span> Contexto</h2><p>Na FV, testes eram manuais e rodados só na véspera do deploy. O resultado: correção de bug gerava novo bug, e ninguém sabia se o sistema continuava funcionando após uma mudança. A confiança no código era baixa e o <strong>medo de deploy</strong> travava a entrega.</p><div class="didactic"><div class="didactic-title">Analogia do cinto de segurança</div>Dirigir sem teste automatizado é como pegar a estrada sem cinto: você até anda, mas basta um solavanco para se machucar. O teste é o cinto que prende o comportamento esperado — se algo mudar, ele avisa antes do acidente. E, como o cinto, só serve se for usado <em>sempre</em>, não só quando lembra.</div><h2><span class="num">2.</span> Diagnóstico</h2><p>Sem suíte automatizada, o tempo de validação cresce com o time e os retornos de bug em produção aumentam. Não existe <strong>gate objetivo</strong> que impeça uma mudança de baixa qualidade de ir a produção.</div><h2><span class="num">3.</span> Solução</h2><p>Criar uma <strong>suíte de testes automatizados em 3 camadas</strong> com <code>pytest</code>, coberta por um <strong>gate objetivo de 80%</strong> aplicado no CI. As camadas: <strong>unitário</strong> (regra pura, rápida, sem I/O), <strong>integração</strong> (use case + adapter real, ex.: Postgres em container) e <strong>e2e</strong> (fluxo ponta a ponta via API). O threshold bloqueia o merge se a cobertura cair abaixo de 80%.</p><p>Configuração centralizada em <code>pyproject.toml</code>:</p><pre><code># pyproject.toml
[tool.pytest.ini_options]
addopts = "-q --cov=src --cov-report=term-missing "
          "--cov-fail-under=80"
testpaths = ["tests"]

[tool.coverage.run]
branch = true
source = ["src"]</code></pre><p>No CI (GitHub Actions), o passo de teste falha o pipeline se a cobertura for insuficiente:</p><pre><code># .github/workflows/ci.yml
steps:
  - uses: actions/setup-python@v5
    with: { python-version: "3.12" }
  - run: pip install -e .[test]
  - run: pytest        # respeita --cov-fail-under=80</code></pre><p>Exemplo das 3 camadas:</p><pre><code># unitario: regra isolada
def test_calcula_imposto_pf():
    assert CalculaImposto().executar(Pedido(100)) == 5

# integracao: use case + repo real (fixture de container)
def test_finaliza_pedido_salva(repo_postgres):
    FinalizaPedido(repo_postgres).executar(Pedido(100))
    assert repo_postgres.buscar(1) is not None

# e2e: fluxo via API
def test_post_pedido_api(client):
    r = client.post('/pedidos', json={'total': 100})
    assert r.status_code == 201</code></pre><h2><span class="num">4.</span> Como funciona (pipeline)</h2><div class="pipeline"><div class="pipeline-head"><span class="pipeline-title">Suíte automatizada com gate 80%</span><span class="pipeline-live"><span class="dot"></span> fluxo em execução</span></div><div class="pipeline-body"><div class="pl-rail"><span class="pl-pulse p1"></span><span class="pl-pulse p2"></span><span class="pl-pulse g"></span></div><div class="pl-steps"><div class="pl-step"><div class="num">1</div><div><div class="name">Configurar <code>pyproject.toml</code></div><div class="desc">Definir <code>--cov-fail-under=80</code> e <code>branch=true</code>.</div><span class="pl-chip"><span class="pl-tag 1">audit</span></span></div></div><div class="pl-step"><div class="num">2</div><div><div class="name">Camada unitária <code>tests/unit/</code></div><div class="desc">Testa regras puras em ms, sem I/O — base da pirâmide.</div><span class="pl-chip"><span class="pl-tag rapido">ok</span></span></div></div><div class="pl-step"><div class="num">3</div><div><div class="name">Camada integração <code>tests/integration/</code></div><div class="desc">Use case + adapter real (Postgres via fixture).</div><span class="pl-chip"><span class="pl-tag precisa container">warn</span></span></div></div><div class="pl-step"><div class="num">4</div><div><div class="name">Camada e2e <code>tests/e2e/</code></div><div class="desc">Fluxo ponta a ponta pela API de verdade.</div><span class="pl-chip"><span class="pl-tag lento">warn</span></span></div></div><div class="pl-step"><div class="num">5</div><div><div class="name">Gate no CI <code>pytest</code></div><div class="desc">Falha o merge se cobertura &lt; 80% ou qualquer teste vermelho.</div><span class="pl-chip"><span class="pl-tag bloqueia">ok</span></span></div></div></div><div class="pl-footer"><span>Cobertura baixa em novo arquivo = PR bloqueado.
