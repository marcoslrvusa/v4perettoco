1. Contexto

O Orquestrador de Automacao V4 executa os fluxos de coleta de metricas, disparo de emails e sincronizacao da operacao FV Marketing. Ele combina n8n (porta 5678), workers Python (porta 8000), Supabase Postgres e painel Next.js (porta 3000), falando com dois sistemas externos: Meta Ads API e Gmail API.

Cada pessoa do time desenhava esse sistema de um jeito. O onboarding de um operador novo levava 3 dias e incidentes de coleta viravam adivinhacao sobre qual peca falhou.

2. Diagnóstico

Faltava um mapa unico em camadas: um diagrama de contexto para explicar em 1 slide, um de containers com portas reais para diagnosticar, um de componentes do n8n (onde 80 por cento das mudancas acontecem) e o codigo critico do retry de coleta, onde um bug apaga verba de trafego dos relatorios.

SintomaCausa
Onboarding de 3 diasSem diagrama de contexto oficial
Incidente vira chat de adivinhacaoSem containers com portas e dependencias
Mudanca no n8n quebra coletaComponentes do n8n nao mapeados

3. Solução

Aplicar os 4 niveis do C4 sobre o sistema real, com Structurizr DSL como fonte unica (workspace.dsl) e Mermaid como espelho que renderiza no repo sem ferramenta extra. Nivel 3 so para o n8n e nivel 4 so para a funcao executar_com_retry, onde bug custa dinheiro.

Decisao chave: PR que muda container exige DSL e Mermaid atualizados juntos, cobrado pelo checklist de revisao.
