Arquitetura

3 camadas · todas obrigatórias

Não são alternativas. Um workflow enterprise TEM que ter as três.
Camada 1
Node-Level · Auto-cura local
retryOnFail + continueErrorOutput em cada nó. Captura falhas transientes (429, 503, timeout) no próprio nó, sem overhead de workflow externo.
~73%
Camada 2
Error Handler Central · Rede de segurança
Workflow único que captura o que escapar da camada 1. Classifica severidade, notifica Slack, persiste na DLQ. 10 nós, validado com n8nac.
10 nós
Camada 3
Circuit Breaker + Dead Letter Queue · Proteção sistêmica
CB evita sobrecarga em APIs fragilizadas (5 falhas → abre por 5 min). DLQ preserva payload completo para replay manual.
2 wf
O que a Camada 1 não cura, a 2 classifica. O que a 2 classifica, a 3 protege e preserva.
05 / 14
Rationale

Por que 3 camadas? As decisões de design

Camada 1 · Node-Level

Problema: 73% dos erros são transientes (429, 503, timeout). Resolver no nó é mais rápido e barato que acionar um workflow externo.

Custo: Zero — config declarativa no JSON.

Trade-off: Não cobre erro de lógica ou validação. Não existe backoff exponencial nativo — pra isso tem Camada 2.

Jr: configurar no nó

Camada 2 · Central

Problema: Se cada workflow tivesse seu próprio error handler, teríamos 10 workflows duplicando lógica. Um central evita isso.

Custo: 1 workflow de 10 nós, validado com n8nac.

Trade-off: Ponto único de falha? Não — se o handler cair, os erros ficam no log do n8n até ele voltar.

Pl: implementar + testar

Camada 3 · CB + DLQ

Problema: Sem CB, APIs frágeis (Chatwoot, Redis) tomam golpe em cascata. Sem DLQ, erro vira "dado perdido".

Custo: Schema Supabase + 1 workflow de monitor a cada 5 min.

Trade-off: Dependência de Supabase. Já temos — custo marginal zero.

Sr: revisar + homologar

Código

Como classificar um erro na prática

Code node de classificação — roda no Error Handler Central quando um erro chega
// Error Handler Central — parse + classificação
const msg = (execution.error?.message || '').toLowerCase();

let errorClass = 'unknown';
let severity = 'info';

if (/5\d{2}|internal server error|upstream/.test(msg)) {
  errorClass = 'server_error'; severity = 'critical';
} else if (/429|rate limit|too many/.test(msg)) {
  errorClass = 'rate_limit'; severity = 'warning';
} else if (/timeout|etimedout|econnrefused/.test(msg)) {
  errorClass = 'timeout'; severity = 'critical';
} else if (/undefined|cannot read|null|not-null/.test(msg)) {
  errorClass = 'data_validation'; severity = 'warning';
} else if (/task runner|disconnect/.test(msg)) {
  errorClass = 'runtime'; severity = 'critical';
}

return [{
  json: {
    correlationId: [workflow.id, execution.id].join('-'),
    severity, errorClass,
    workflowName: workflow.name,
    failedNode: execution.lastNodeExecuted,
    errorMessage: (error.message || '').substring(0, 500),
    executionId: execution.id,
    timestamp: new Date().toISOString(),
  }
}];

Consultas que você vai rodar todo dia

2. Circuitos abertos agora

3. Top workflows com erro (7d)
SELECT workflow_name, COUNT(*) AS total
  FROM error_dlq
  WHERE created_at > now() - INTERVAL '7 days'
  GROUP BY workflow_name
  ORDER BY total DESC LIMIT 10;
4. Erros não revisados
SELECT * FROM error_dlq
  WHERE status = 'pending_review'
  ORDER BY severity DESC, created_at DESC
  LIMIT 50;

Anti-Patterns

O que não fazer — aprenda com os erros

Erros reais que vimos nos workflows SDR IA
onError sem main[1] — Erro descartado silenciosamente. Sempre use continueErrorOutput + segundo output conectado.
Retentar 4xx (exceto 429) — Queima API credits à toa. Se é erro do cliente (400, 401, 403, 404), não vai mudar na próxima tentativa. Só retentar 5xx/429/timeout/DNS.
Error workflow no mesmo canal — Se o workflow de erro usa o mesmo Slack que o principal, uma falha no Slack cria recursão infinita. Use canais separados.
Responder 200 quando deu erro — Se você responde 200 após uma falha, quem chamou nunca sabe. Propague o status HTTP correto.
Não publicar o error handler — Código antigo rodando mesmo depois de "corrigido". Sempre publish (Shift+P) após configurar.
