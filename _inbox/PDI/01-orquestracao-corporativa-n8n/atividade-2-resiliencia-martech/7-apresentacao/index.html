SLIDE 02 / 08
Problema

Síncrono, frágil e às cegas

Fila

Requisições MarTech processadas dentro do webhook. Em picos (campanha, importação), a instância trava e o cliente não recebe ACK.

Payload pesado

Processamento de 10k+ itens roda de uma vez. Um timeout no meio perde tudo — o job recomeça do zero.

Sem observabilidade

Falha de sync não é registrada. Divergência entre o esperado e o syncado só é descoberta quando o cliente reclama.

SLIDE 03 / 08
Arquitetura

Pipeline assíncrono em 4 etapas

1

[CC] MT Queue Gateway

Webhook de entrada. Enfileira em mt_jobs e responde ACK 202 imediato. Idempotência por job_key.

2

[CC] MT - Queue Worker

Polling a cada 15s. Respeita o semáforo mt_concurrency (slots por fila) e delega o processamento pesado.

3

[CC] MT - Heavy Payload Processor

Normalização em chunks (JS) + enriquecimento opcional (Python). Grava checkpoint mt_job_progress por chunk.

4

[CC] MT - CRM Sync Observabilidade

Endpoint /mt/crm-sync. Registra mt_sync_log, atualiza mt_crm_health e detecta drift.

SLIDE 05 / 08
Detecção de divergência

Drift — detectado antes do cliente

// Tolerância configurável (default 5%)
esperado   = 1200   // o que o workflow devia syncar
confirmado = 1184   // o que o CRM confirmou
drift      = (1200 - 1184) / 1200 ≈ 1.3%  // ok, dentro da tolerância

// Divergência real:
esperado   = 1000   // importante manter min < 5%
confirmado = 860
drift      = 14%   // > 5% → mt_sync_delta aberto + alerta

O envelope de sync calcula hash de payload e resposta; o Observabilidade decide se há drift e alimenta o dashboard em tempo real.

SLIDE 06 / 08
Payload pesado

Retomada do chunk, não do zero

// mt_job_progress — checkpoint por chunk
chunk_index  4 / 10
status       running

// Falha no chunk 4? Redispara do 4 (não do 0)
Queries:
  SELECT * FROM mt_job_progress WHERE job_id = :id

// Worker re-enfileira com backoff exponencial:
retry_at   = now + 30s   // tentativa 1
retry_at   = now + 1m    // tentativa 2
retry_at   = now + 2m    // tentativa 3
max_attempts = 3

O envelope de erro (atividade 1, Error Handler Central) continua tratando o que escapar daqui.
