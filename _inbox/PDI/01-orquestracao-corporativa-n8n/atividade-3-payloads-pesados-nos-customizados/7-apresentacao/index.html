SLIDE 02 / 08
Problema

"Nó que faz tudo" = payload que trava

Memória

Payload inteiro carregado na memória + { ...item } por iteração em 100k itens = OOM e event loop bloqueado.

Complexidade

JSON.parse no loop e buscas por item (.find, indexOf) viram O(n²). Cada re-parse custa caro.

Duplicação

Mesmo transform copiado entre dezenas de workflows. Expressões inline difíceis de manter, sem biblioteca compartilhada.

SLIDE 03 / 08
Arquitetura

Payload pesado em 5 etapas, O(n)

1

Payload pesado (10k–100k itens)

Chega via webhook. Antes: map().filter() encadeado + cópias por item → OOM.

2

Parse + Chunk (JS)

Decodifica o JSON 1x na entrada e quebra em chunks de 1000. Nunca re-parseia dentro do loop.

3

Normalize in One Pass (JS)

Filtra, dedupe (Set por chave primitiva) e transforma no mesmo loop — O(n), cópia mínima.

4

Enrich Python (Python)

Enriquecimento e agregação com collections/itertools — só stdlib, sem pandas.

5

Return Metrics (JS)

Entrega processedItems, deduped, durationMs, itemsPerSecond — base do monitoramento.

SLIDE 04 / 08
Complexidade

De O(n²) para O(n)

// ANTES: busca por item dentro do loop → O(n²)
items.forEach(item => {
  const x = items.find(o => o.id === item.ref);  // 100k × 100k
});

// DEPOIS: Set de dedupe + UMA passada → O(n)
const seen = new Set()();
for (const item of items) {
  if (seen.has(item.id)) continue;   // sair cedo
  seen.add(item.id);
  out.push({ json: normalize(item) });  // cópia mínima
}

Filtro barato antes de transformação cara; dedupe por chave primitiva, nunca por objeto.
