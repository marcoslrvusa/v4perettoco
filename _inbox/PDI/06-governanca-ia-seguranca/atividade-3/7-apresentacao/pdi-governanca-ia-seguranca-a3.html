1. Contexto

Tokens de Meta Ads, Google, CRM, banco e webhooks circulam entre workers, CIs e maquinas do time sem inventário, sem dono e sem prazo de troca. Chave sem dono e chave eterna.

Esta atividade fecha a causa: cofre central, entrega por referência, rotação com prazo e varredura que falha o build.

2. Diagnóstico

Segredo em chat, planilha ou commit da acesso a verba de mídia e base de leads; a troca emergencial vira madrugada porque ninguém sabe onde cada chave está usada. O custo do vazamento é proporcional ao tempo de exposição, e hoje esse tempo é indefinido.

SintomaRiscoCorreção
.env no chat ou wikiExposição permanenteCofre + referência
Chave estática no CIAbuso silenciosoOIDC ou rotação curta
Sem rotaçãoJanela infinita30/90/180 dias com dono

3. Solução

Standard com princípios, tabela de guarda e entrega, prazos e resposta a vazamento em 5 passos. Código secrets_audit.py executável: 5 famílias de padrões reais, checagem de .gitignore e exit code para o CI. Comandos do GitHub Docs verificados na entrega.

gh secret set NOME_DO_SECRET
gh secret set NOME_DO_SECRET < secret.txt
gh secret set --env PROD NOME_DO_SECRET
gh secret list
  • Produção no cofre, CI em secrets por ambiente, local em `.env` fora do git
  • Dynamic secrets com TTL onde o provider suporta
