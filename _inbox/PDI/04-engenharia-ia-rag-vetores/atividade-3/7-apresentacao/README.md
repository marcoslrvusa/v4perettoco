# Orquestracao Multi-agente com Handoffs e Isolamento

Engenharia de IA

<h2><span class="num">1.</span> Contexto</h2>

<p>Um único LLM gigante vira um "faz-tudo-mal". Sistemas <strong>multiagente</strong> dividem o trabalho: um <em>supervisor</em> recebe a tarefa e delega a <em>workers</em> especializados (pesquisa, código, revisão). O pulo do gato é a <strong>orquestração</strong>: quem decide o próximo passo, como os agentes passam o bastão (<em>handoff</em>) e onde guardar <strong>memória</strong> entre turnos.</p>

<div class="didactic"><div class="didactic-title">Analogia da redação</div>O supervisor é o editor-chefe. Ele não escreve a matéria: distribui pautas. O repórter apura, o revisor corrige, o artefinalista diagrama. O <strong>handoff</strong> é o briefing que passa de um pro outro; a <strong>memória</strong> é o arquivo da redação pra não reinventar a roda a cada edição.</div>

<h2><span class="num">2.</span> Diagnóstico</h2>

<p>Tudo rodava num prompt monolítico de 8k tokens. Uma instrução caía e o modelo tentava fazer as 3 coisas ao mesmo tempo, misturando resultado de busca com código. Sem <em>roles</em> claros, o erro de uma etapa contaminava a outra e não havia ponto de retomada.</p>

<div class="callout"><strong>Raiz do problema:</strong> ausência de fronteira entre funções. Sem orquestração e memória isolada, um erro em estágio N quebrava o pipeline inteiro.</div>

<h2><span class="num">3.</span> Solução</h2>

<p>Framework de orquestração com <strong>supervisor + 3 workers</strong> (researcher, coder, reviewer). O supervisor roteia por intenção; cada worker tem prompt e ferramentas próprias; o <em>handoff</em> passa só o contexto necessário; a <strong>memória</strong> é um store de curto prazo (turno) + longo prazo (aprendizado).</p>
