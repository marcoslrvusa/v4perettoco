	🟡 Fase 2 — Contexto ↔ Supabase (11h)
		Problema
			/contexto só escreve em disco local
			Quebra o loop de contexto entre agentes
		Solução
			Modificar /contexto para chamar context.py push ao final
			Campos extraídos: tom_de_voz, histórico, oferta, facts
			Flag --auto-sync on/off
		Validação
			Rodar /contexto → context.py pull retorna mesmos dados
		Dependências
			Nenhuma (já tem schema + script)
	🟡 Fase 3 — Copy: Briefing + Produção (28h)
		3.1 — Skill de Briefing (copy-briefing)
			O que faz
				Puxa contexto do cliente
				Busca memórias similares
				Gera brief estruturado
				Salva em docs/briefings/
			Input: demanda de conteúdo
			Output: brief com objetivo, tom, referências, formato
		3.2 — Skill de Produção (copy-producao)
			O que faz
				Lê brief estruturado
				Puxa contexto do cliente
				Gera rascunho completo
				Registra memória do que foi produzido
			Input: brief markdown
			Output: copy pronta (LP, email, anúncio, blog)
		Fluxo completo
			Demanda → Briefing → Produção → Entrega
		Depende: Fase 2
	🟡 Fase 4 — LiteLLM Gateway (19h)
		Objetivo
			Todo agente chama modelo pelo gateway
			Não mais direto em cada provider
		Componentes
			LiteLLM como systemd na VPS
			Roteamento por task-type
				Copy → Gemini
				Análise → DeepSeek
				Código → GPT-OSS
				Estratégia → DeepSeek
				Design → Gemini
			Fallback automático
			Rate limiting centralizado
			Dashboard de custo/uso
		Configuração
			opencode.json aponta para LiteLLM
			Skill geral-gateway-modelos
		Depende: Fase 1 (LiteLLM já instalado)
