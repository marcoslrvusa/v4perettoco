Arquitetura Técnica AI Visibility

AI Visibility
Technical Docs

Guia completo de implementação, componentes, deploy e operação da plataforma AI Visibility.

Visão geral da arquitetura

Camadas da solução
Front‑end, API, automação.

  • • Frontend (Portal) – React SPA hospedado no Vercel, usando portal/ (HTML, CSS, JS) para captura de dados e visualização.
  • • API Serverless – Vercel Functions (/api/crawl.js, /api/visibility.js) responsáveis por crawling de resultados IA, extração de citações e cálculo de métricas.
  • • Automação – Scripts em scripts/ (Node.js) que rodam jobs diários (extrairability, citation‑checker, dashboard‑generator) via cron ou GitHub Actions.
  • • Data Store – JSON files em data/ (ou bucket S3) como fonte de verdade para relatórios.
  • • CI/CD – GitHub Actions que lint, testam (Jest) e deployam no Vercel automaticamente.
Frontend – Portal

Componentes principais
HTML, CSS, JS.

O portal está em ai-visibility-v4/portal/ e inclui:

  • index.html – página de entrada com form de captura de domínio.
  • app.js – lógica de interação, consumo da API /api/visibility, renderização de tabelas e gráficos.
  • proposer.js – módulo que gera propostas personalizadas a partir de dados de diagnóstico.
  • styles.css – estilos baseados no tema V4 (cores, tipografia, responsividade).

Para desenvolver localmente:

cd ai-visibility-v4/portal
npm install   # instala dependências de build (esbuild, tailwind opcional)
npm run dev   # servidor local na porta 3000
Vercel Functions

Endpoints serverless
Implementação.

/api/crawl.js – realiza crawling de URLs fornecidas, extrai texto limpo (via defuddle) e devolve snippets.

/api/visibility.js – consulta engines de IA (OpenAI, Perplexity) para buscar citações da marca, calcula score de visibilidade e devolve JSON estruturado.

Exemplo de chamada:

curl -X POST https://your‑project.vercel.app/api/visibility \
  -H "Content-Type: application/json" \
  -d '{"brand":"V4","domains":["v4.com","blog.v4.com"]}'
Scripts de automação

Rotinas de backend
Agendamento.

  • extractability.js – varre URLs cadastradas, extrai conteúdo e grava em data/extracts/.
  • citation-checker.js – consulta a API de IA para citar a marca; grava resultados em data/citations/.
  • dashboard-generator.sh – combina métricas e gera relatórios HTML estáticos em public/reports/.

Agendamento recomendado via GitHub Actions (cron @daily) ou serviço externo (Cronitor).

CI / CD

Fluxo de entrega
Automatizado.

# .github/workflows/deploy.yml
name: Deploy AI Visibility
on:
  push:
    branches: [main]
jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup Node
        uses: actions/setup-node@v3
        with:
          node-version: '20'
      - run: npm ci
      - run: npm run lint
      - run: npm run test
      - name: Deploy to Vercel
        uses: amondnet/vercel-action@v20
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}
          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}
          github-token: ${{ secrets.GITHUB_TOKEN }}
Boas‑práticas AIO

Checklist técnico
Garantia de qualidade.

  • ✅ Conteúdo estruturado com schema.org (FAQ, Article, Product) para melhorar extração.
  • ✅ URLs canônicas, hreflang e sitemap XML devidamente configurados.
  • ✅ Responsividade e performance (LCP < 2 s, CLS < 0.1).
  • ✅ Multilinguismo – verifique traduções e hreflang.
  • ✅ Acessibilidade – contraste, aria‑labels, WCAG 2.1 AA.
  • ✅ CSP restritiva – apenas scripts necessários.
  • ✅ Revisão de conteúdo trimestral – atualizar factual e otimizar para novas consultas IA.
  • ✅ Monitoramento de citações via citation-checker.js – alertas Slack.
  • ✅ Backups diários de data/ para preservar histórico de métricas.
Monitoramento & Alertas

Observabilidade
Visibilidade operacional.

Utilizamos:

  • Vercel Logs – monitoramento de erros de funções.
  • Prometheus + Grafana – métricas customizadas (citações por dia, tempo de crawling).
  • Slack Webhooks – alertas de falhas críticas (crawling falhou, quota excedida).
  • GitHub Issues – automação cria issue para falhas recorrentes.
