FAQ

Technical reference

Arquitetura, uso e conceitos do sistema multi-agente.

O que é a Agent Orchestra V4?
É um sistema multi-agente que transforma as 62 skills do Builders Hub V4 em 20 subagentes orquestráveis. Cada agente domina de 4 a 8 skills e pode ser invocado sozinho ou em formação de time. A arquitetura segue 3 tiers: especialistas de domínio (execução), orquestradores de time (coordenação) e CMO orchestrator (estratégia).
Como agentes se relacionam com skills?
Skills são instrumentos individuais (cada uma sabe fazer uma coisa). Agentes são músicos que combinam múltiplos instrumentos. Orquestradores são maestros que coordenam músicos em uma sinfonia. A Agent Orchestra não substitui skills — ela as organiza em um sistema coerente com cadeias de valor, gates de qualidade e output padronizado (JSON/Markdown).
Como funciona o quality gate?
@revisor é o quality gate obrigatório do sistema. Ele não edita nada — apenas valida: (1) números conferem com fontes, (2) formato segue padrão V4, (3) recomendações alinham com OKRs, (4) tom é apropriado. Se algo estiver errado, ele reporta e você pede correção. Todo output de agente deve passar pelo revisor antes de entrega.
Posso criar formações customizadas?
Sim. Qualquer combinação de agentes funciona. Use a sintaxe @agente1 + @agente2 + @agente3 na sua mensagem. O primeiro agente assume liderança. Os padrões suportados são: cadeia linear (pipeline), hub & spoke (orquestrador central), malha colaborativa (mesh) e event-driven (flag-triggered).
Agentes funcionam com dados reais?
Sim. @analista-dados, @flag-* (churn, okr, operacao, roi) e @automacao-analytics acessam dados reais de campanhas, OKRs, NPS, CSAT e métricas. A skill v4mos-dados-meta-ads puxa dados ao vivo de Meta Ads via API. Use @contexto para carregar a KB do cliente antes de invocar os agentes.
Onde está a documentação completa?
O arquivo ORCHESTRA.md na raiz do projeto tem: catálogo detalhado dos 20 agentes com skills fonte, 8 formações de time com lineup completo, 5 padrões de orquestração com diagramas, 3 cenários reais passo-a-passo (churn recovery, product launch, growth optimization) e guia rápido de uso.
